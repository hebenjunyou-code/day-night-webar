WebAR 起動用 QR（スマホがメイン）

このQRの役割： スマホがカメラ付きブラウザ（Safari / Chrome など）だけでインストール不要の WebAR が開きます。アプリのストア配布は不要です。

PCの画面は「ARの視聴用モニター」ではなく、このページのように起動リンクの発行やファイルの公開・検証が主になります。

いまブラウザで file:// のまま開いています

QRにしたいHTTPS（または開発用の適切なhttp）のURLがネットワーク上に無い状態です。このままQRにしてもスマホではほぼ開けません。恒久運用には下の GitHub Pages などがおすすめです。
  1. 手元開発： ローカルサーバーをPCで動かす → 同一Wi‑FiならPCのIPv4のURL／外出先には ngrok 等のHTTPSで …/day-night-ar.html を入力欄へ。
  2. PCのみ動作確認： 「PC用 localhost」でURL入力 → PCのブラウザのアドレス欄に貼って開く（QRは使わない）。

  


  

    「QRコードを読み込む」と スマホのブラウザで day-night-ar.html が開き、画面の案内どおりカメラ許可でARが動きます。

    下の入力欄には、そのWeb上の…/day-night-ar.htmlのフルURL を入れ、「QRを表示」でアプリ起動用QRを出します。

    127.0.0.1 / localhost をQRにするとスマホは自分自身に接続して失敗するため、このページではブロックしています。
  


  

    
いつでも開けるURLを残したい（GitHub など）

    

      アプリ本体は単体HTMLでも、ブラウザはウェブ経由で取りにいくため、どこかのサーバー／ホスティング上に置くことになります。無料でも手軽な例はGitHub Pagesです。
    

    
    
      
  1. GitHub でリポジトリを作成し、day-night-ar.html をアップ（ユーザー名.github.io にするか、プロジェクトサイトなら/REPO/下）。
    2. 
      
  2. リポジトリ Settings → Pages でソースブランチを指定しサイトを公開する。
    3. 
      
  3. 表示された https://…/day-night-ar.html を、このページの入力欄へ貼り「QRを表示」。
    4. 
    

    
GitHub Pages の公式説明（英語） · Cloudflare Pages / Netlify なども同等のHTTPSホストとして使えます。

  


  

    
開発中：同一Wi‑FiのスマホからPCのサーバーへ繋ぐ

    

      PC で ipconfig の IPv4（例 192.168.1.15）を確認。サーバーが 0.0.0.0 で待ち受けている状態で（下のコピーコマンド参照）、そのIPからURLを組み立ててQRを出します。
